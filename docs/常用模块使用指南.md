# FPGA 开发常用模块指南

2026.10.11 最后一次修订

## 1. 前言

我为该项目提供了一些常用的模块，供大家在开发时参考和使用。这些模块都是经过反复验证和测试的，具有良好的可复用性和可维护性。因此我非常建议大家直接复用这些模块。每个模块对应的文件内部都有相应的注释，大家可以直接阅读这些注释来了解模块的功能和使用方法。

## 2. 定点数计算模块

该部分模块位于文件夹 `src/fixed_points` 下，主要服务于定点数的相关计算。

### 2.1. 定点数概述

我们约定使用 Q 格式表示定点数。一个无符号 Q 格式定点数可以表示为 `UQM.N`，其中 `M` 表示整数部分的位数，`N` 表示小数部分的位数。一个有符号 Q 格式定点数可以表示为 `SQM.N`，`M` 表示整数部分的位数（包括符号位），`N` 表示小数部分的位数。

不难发现，`UQM.N` 和 `SQM.N` 的总位数都是 `M + N`，它们所能表示的数的范围分别是 $[0, 2^M - 2^{-N}]$ 和 $[-2^{M-1}, 2^{M-1} - 2^{-N}]$，精度都是 $2^{-N}$。

我们总是用位宽为 `M + N` 的信号来表示定点数。在 Verilog 中，有符号定点数需要用 `signed` 关键字声明，而无符号定点数不需要。在下面的例子中，我们分别声明了一个有符号定点数 `a` 和一个无符号定点数 `b`，它们的位宽都是 16 位，整数部分都是 8 位，小数部分都是 8 位。

```verilog
reg signed [15:0] a;  // 有符号定点数，SQ8.8
reg [15:0] b;  // 无符号定点数，UQ8.8
```

有符号数使用补码表示。Verilog 支持 `a <= -1;`，对于 16 位的 a，这会写入编码 16'hFFFF。带位宽的负数字面量应写成 `-16'sd1`，不能写成 `16'sd-1`。需要区分原始整数编码与 Q 格式实数值：当 a 表示 SQ8.8 时，编码 -1 对应实数 -1/256；若要表示实数 -1.0，应写入 `a <= -16'sd256;`，即编码 16'hFF00。

出于某些原因，我们需要存储 Q 格式的定点数常量。比如，假设我们要存储 123.456 的 UQ8.8 格式常量，就要先用计算器计算出这个实数的定点数常量值：

$$ 123.456 \times 2^8 = 31605.696 \approx 31606 $$

由此定义

```verilog
localparam [15:0] CONST = 16'd31606;  // UQ8.8, 123.456
```

建议定义 Q 格式定点数常量时，在末尾注明其 Q 格式与对应的实数值，以便于理解和使用。

### 2.2. 定点数标准化模块

在开发的过程中，我们经常要对不同格式的定点数进行相互转化。因此我开发了 `unsigned_fp_norm` 和 `signed_fp_norm` 两个模块，分别用于无符号定点数和有符号定点数的标准化。模块的输入是一个 UQ(QII).(QIF) 或 SQ(QII).(QIF) 格式的定点数，输出是一个 UQ(QOI).(QOF) 或 SQ(QOI).(QOF) 格式的定点数。模块的功能是将输入的定点数标准化为输出的定点数格式。

模块全部采用组合逻辑，基本不需要考虑延迟。

我没有提供有符号定点数与无符号定点数之间的转化模块。因为对于大于 0 的有符号定点数，它们的二进制表示与无符号定点数是相同的，因此它们的转换比较简单。下面给出了有符号定点数与无符号定点数之间的转换方法。

```verilog
reg signed [15:0] a;  // 有符号定点数，SQ8.8
reg [15:0] b;  // 无符号定点数，UQ8.8

// 有符号定点数转无符号定点数
wire [15:0] c = a[15] ? 16'd0 : a;  // 如果 a < 0，则 c = 0，否则 c = a

// 无符号定点数转有符号定点数
wire signed [16:0] d = $signed({1'b0, b});  // 高位补 0 作为符号位，扩展位宽为 17 位
```

这里需要注意从有符号转换为无符号时要处理负数的情况，从无符号转换为有符号时要处理溢出的情况。

一般而言，我们会避免将小于 0 的有符号定点数转换为无符号定点数。而将首位为 1 的无符号定点数转换为有符号定点数时，我们会优先进行高位补 0 作为符号位的处理，虽然这种方法会扩展位宽，但不会产生数据失真。

`$signed` 是 Verilog 的系统函数，用于强制将一个无符号数视为有符号数。它的作用是将输入的无符号数的最高位作为符号位进行解释，从而得到一个有符号数的表示。

### 2.3. 定点数四则运算模块

定点数的运算实际上比想象的要复杂很多，而且还有很多坑。比如，不同格式的定点数的对齐、运算结果的格式等。因此我对定点数的四则运算进行了封装，提供了 `signed_fp_add`、`signed_fp_sub`、`signed_fp_mult`、`signed_fp_div`、`unsigned_fp_add`、`unsigned_fp_sub`、`unsigned_fp_mult` 和 `unsigned_fp_div` 八个模块，分别用于有符号定点数和无符号定点数的加减乘除运算。运用这些模块时，用户可以自由指定输入和输出的定点数格式，模块会自动进行标准化处理，从而避免数据失真。

因为我只做了同符号类型的运算封装，所有如果用户需要将一个 UQ 定点数和一个 SQ 定点数进行运算，那么用户需要先将 UQ 定点数进行补 0 处理转化为 SQ 定点数，然后再进行运算。

因为通常来讲定点数运算消耗的资源比较大，所以我把这些模块都设计为了时序逻辑电路防止时序冲突。因此，**所有定点数的计算都不可避免地会有一个时钟周期的延迟**。用户输入数据后，必须要等待一个时钟周期才能得到计算结果。

模块的输出有锁存，因此只要用户不改变输入数据，那么一拍后的输出数据就会保持不变。如果想要计算别的数，那么直接改变输入数据即可，模块会在下一个时钟周期输出新的计算结果并锁存。

在调用这些模块进行运算时，需要注意资源的占用消耗。通常来讲，资源占用的相对大小为：

变量除以变量 > 常量除以变量 > 变量乘以变量 > 变量乘以常量 > 变量加减变量 > 变量加减常量

其中，所有的变量除以常量均可转化为变量乘以常量进而减小资源消耗。

尽量不要使用涉及到变量的除法。

## 3. 信号检测模块

该部分文件位于文件夹 `src/signal_detection` 下，主要服务于信号的同步和边沿检测。

### 3.1. 信号同步模块

从 FPGA 外部送来的信号相对于 FPGA 内部的时钟信号来说，通常是异步的。为了避免亚稳态问题，我们需要对这些异步信号进行同步处理。为此，我提供了 `signal_sync` 模块，用于将异步信号同步到 FPGA 内部的时钟域。其原理是通过二级寄存器打拍消除亚稳态。

### 3.2. 信号边沿检测模块

在不同接口的通信握手中，我们经常遇到需要在某个时钟域检测某个信号的上升沿或下降沿的情况。为此，我提供了 `signal_edge_detector` 模块，用于检测信号的上升沿和下降沿。该模块的输入是一个信号，输出是两个信号，分别表示输入信号的上升沿和下降沿。

详细来讲，就是 `signal_posedge` 和 `signal_negedge` 会在检测到 `signal_sync` 的上升沿和下降沿时输出一个 `clk` 时钟周期的高电平脉冲。在实际应用时，可以在 `clk` 时钟域下的 `always` 块内通过 `if` 语句判断上跳变或下跳变事件的发生，这样能够保证跳变事件触发且仅触发一次。

这里需要注意的是，输入的信号应当是相对于所用时钟域同步的信号。如果不是，请先使用 `signal_sync` 模块将其同步到所用时钟域。一般而言，FPGA 内部产生的信号都是同步信号，外部送来的信号则通常是异步信号。

## 4. 其他常用模块

该部分模块位于文件夹 `src/common` 下，主要服务于其他常用功能。

### 4.1. 分频模块

`clock_divider` 模块用于将输入时钟信号进行分频，输出一个频率为输入时钟信号频率的 `1/NUM_DIV` 的时钟信号。这里一定要注意，**`NUM_DIV` 必须是大于等于 2 的偶数**，否则输出的时钟信号会有异常。

### 4.2. 有限状态机模块

在 FPGA 开发中我们会大量地使用状态机，因此我对其功能进行了简单的封装。我们规定项目中的所有状态机均采用三段式表达，即状态转换、状态转移和状态输出。

所谓状态转换，就是运用时序逻辑 `always` 块来描述将下一时刻的状态赋值到当前状态的过程。这个非常简单，做一个 D 触发器就可以了，而且对于不同的状态机，该部分代码总是固定的，因此我将其封装成了 `fsm` 模块。该模块输入 `stn` 下一时刻的状态，输出 `stc` 当前时刻的状态。用户只需要在 `stn` 中写入下一时刻的状态即可，模块会自动将其赋值到 `stc`。

所谓状态转移，就是运用组合逻辑 `always` 块来描述由当前状态和输入信号决定下一时刻的状态的过程，即根据 `stc` 和输入信号计算 `stn`。这个部分的代码对于不同的状态机是不同的，因此我没有对其进行封装。

所谓状态输出，就是运用时序逻辑 `always` 块来描述由当前状态和输入信号决定输出信号的过程，即根据 `stc` 和输入信号计算输出信号。这个部分的代码对于不同的状态机也是不同的，因此我也没有对其进行封装。

下面给出运用 `fsm` 模块的状态机的一个简单例子。

```verilog
localparam S0 = 2'b00, S1 = 2'b01, S2 = 2'b10, S3 = 2'b11;

// 这里需要注意一下状态变量的类型。通常情况下，stc 是只读的，stn 是可读可写的。这是因为 stc 是由 fsm 模块输出的，而 stn 在状态转移部分由 stc 和输入信号计算得到。在输出部分，我们只根据当前状态和输入信号计算输出信号，不强制需要读取 stn 的值。这也是为什么我要将状态机做成模块的原因，因为通常来讲 input 变量总是能溯源到一个 reg 变量，而 output 变量只能引到一个 wire 变量，这正好与我们之前推导的状态变量的读写性质相符。
// 总之，这种写法可以禁止用户对 stc 进行写入。另外，在状态输出阶段，stn 理论上来讲也没有必要进行读取，但实际工程上可能为了精简代码而在状态输出阶段读取 stn 的值，这种做法是允许的，所以没有做限制。
wire [1:0] stc;  // 当前时刻的状态，线变量只读
reg [1:0] stn;  // 下一时刻的状态，寄存器变量可读可写

// 状态转换
fsm #(
    .W(2),
    .INITIAL_STATE(S0)
) fsm_u (
    .clk(clk),
    .rst_n(rst_n),
    .stn(stn),
    .stc(stc)
);

// 状态转移
always @(*)
begin
    case (stc)
        S0: stn = in1 ? S1 : S0;
        S1: stn = in2 ? S2 : S1;
        S2: stn = in3 ? S3 : S2;
        S3: stn = in4 ? S0 : S3;
        default: stn = S0;
    endcase
end

// 状态输出
always @(posedge clk or negedge rst_n)
begin
    if (!rst_n)
    begin
        out <= 2'd0;
    end
    else
    begin
        case (stc)
            S0: out <= in5 ? 2'd0 : 2'd1;
            S1: out <= in6 ? 2'd1 : 2'd2;
            S2: out <= in7 ? 2'd2 : 2'd3;
            S3: out <= in8 ? 2'd3 : 2'd0;
            default: out <= 2'd0;
        endcase
    end
end
```
