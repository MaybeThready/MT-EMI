# test_velocity：24键与压力联合测试

本工程位于 `test/velocity`，顶层源码是 `../../src/test/test_velocity.v`，顶层名为 `test_velocity`。沿用现有 `test_keyboard_interaction` 的真实键盘、UI、32声部机架和I2S链路，接出两片4067控制和六个诊断灯；不加入效果器、旋钮、按钮菜单、弯音ADC或音色存储。

此测试读取实际触摸输入，不再自动每秒触发。所有已有公共RTL及主工程配置保持原样，仅增加独立测试文件和工程。工程、CST、SDC与DO中的共享路径均为相对路径；`impl`、`.gprj.user`、仿真工作库和本地 `modelsim.ini` 为生成物。

当前联合功能仿真通过，但尚未定位实物“只有第1键有力度”的原因，不能以仿真代替模拟电路测量。新增自动诊断版已完成综合和布线：建立/保持违例均为0，最差建立余量+0.071ns、保持+0.247ns、恢复+3.333ns、移除+0.258ns，最小脉宽余量+0.492ns。建议先下载该版本定位；正式32声部版需另看自己的时序报告，不能套用单声部诊断版的余量。

正式32声部版本轮也已重新完成综合、布线和位流生成，仍有155个建立时间违例端点、最差-0.496ns；保持+0.247ns、恢复+1.529ns、移除+0.368ns，尚未完成时序收敛。其位流保存于 `impl/keyboard/test_velocity.fs`，本轮定位优先使用时序已通过的自动诊断版。

`impl/functional/test_velocity.fs`是旧快照，不作为本次重新检查后的下载入口。当前两个构建脚本分别保存自己的位流和时序报告，避免Gowin同名输出互相覆盖：

- `build.tcl`：真实触摸键盘、24路压力、32声部，保存到 `impl/keyboard/test_velocity.fs`。
- `build_auto.tcl`：不依赖触摸输入的逐键诊断，保存到 `impl/auto/test_velocity_auto.fs`。

`build_auto.tcl`在忽略提交的 `impl/auto_build` 中生成独立工程，中间工程的源文件和约束路径仍为相对路径。它不覆盖正式键盘工程的 `impl/pnr`；下载时仍建议明确选择以上两个分类目录，避免选到旧文件。

## 仅第1键有力度时的诊断

先运行 `build_auto.tcl`，下载 `impl/auto/test_velocity_auto.fs` 到SRAM，然后按下并松开S0。接线与下表相同，不需要触摸任何键。此顶层仅用单声部，但仍然使用原keyboard_driver内的24路压力扫描和ADCLRC、真实UI/音频机架/I2S。

每约2秒选择下一个发声音符，从FSR1到FSR24循环，完整一轮约48秒；内部仍然连续扫描全部24路，LED不表示4067地址保持2秒。LED0～LED4分别代表1、2、4、8、16；把亮灯的权值相加，再加1，就是当前用于控制音量的FSR编号。LED5仍是故障灯，应熄灭。开始时LED0～4全灭表示FSR1；只有LED0亮表示FSR2；只有LED1亮表示FSR3。

在对应时间窗内轻压/重压当前FSR，音量应变化；按其他FSR不应影响当前键。未施压仍可能有5%最低力度的轻微声音，这与正式UI一致。自动换键可能使旧音重新起音或被单声部抢占，这是该诊断的预期行为。

若自动诊断第2路正常、真实触摸版第2键异常，继续排查触摸顺序与压力通道对应、正式版时序。若自动诊断也只有第1路有效，应测量地址/使能信号及各路模拟电压，不能凭LED5灭判定模拟电路正常。诊断版本不代表已确认修复实物问题。

新增非同号映射仿真：`do do/test/run_test_velocity_routing.do`，24个键分别单独分配到第0声部，检查各自压力及邻键隔离。自动模式回归：`do do/test/run_test_velocity_auto.do`，检查无触摸输入下的24路压力快照、第2键调压、LED键号及实际PCM输出。

2026-11-01重新检查结果：原完整联合回归184组键盘数据、712帧音频、左右各711个I2S字通过；非同号映射24键/32声部/96组输出通过；自动模式第2键连续调压与邻键隔离通过，观察到2040个非零PCM结果。三项ModelSim回归均为0错误、0警告。ADC行为模型不模拟真实模拟电压和精度，实物仍需按上述自动诊断确认。

## 接线

保留之前已验证的键盘和MAX98357A接线，增加/保留以下4067控制线。`status_led`按实物LED0～LED5编号，均低电平亮。

| 信号 | 板上位置 | FPGA球位 | 连接 |
| --- | --- | --- | --- |
| `clk_core` | 核心板50MHz晶振 | P16 | 板内，无需外接 |
| `rst_n` | S0 | K16 | 板内，按下复位 |
| `load_n` | J23.1 | U16 | 两块触摸板74HC165的低有效并行装载 |
| `key_clk` | J23.3 | U15 | 两块触摸板74HC165移位时钟 |
| `data_a` | J23.5 | W21 | A板12键串行数据，触摸为1 |
| `data_b` | J23.7 | P21 | B板12键串行数据，触摸为1 |
| `mux_addr[0]` | J23.13 | T23 | 两片4067的S0 |
| `mux_addr[1]` | J23.15 | R25 | 两片4067的S1 |
| `mux_addr[2]` | J23.17 | W23 | 两片4067的S2 |
| `mux_addr[3]` | J23.19 | U24 | 两片4067的S3 |
| `mux_en_a_n` | J23.21 | AC26 | 第一片4067低有效EN |
| `mux_en_b_n` | J23.23 | AB25 | 第二片4067低有效EN |
| `i2s_bclk` | J26.11 | C21 | MAX BCLK |
| `i2s_lrck` | J26.9 | B20 | MAX LRC/LRCK |
| `i2s_dout` | J26.7 | B19 | MAX DIN |
| `sd_mode_n` | J26.5 | A17 | MAX SD，高电平选择左声道 |

两片4067地址共接，EN分别连接。两个COM共用原来已测通的模拟前端，缩放后接 **J3.1/N12（ADCV+）**；**J3.3/P11（ADCV−）接模拟地**，J3.2/4为GND。沿用已经单路测通的FSR供电、缓冲、缩放及共地方式，最终ADC输入保持0～1V。不要把3.3V模拟电压直接送入ADC，也不要给N12/P11增加LVCMOS33约束。

压力与琴键按下面映射接线，尤其不能把4067按12+12分配：

| 琴键 | 键下标/FSR编号 | 4067通道 | 音高范围 |
| --- | --- | --- | --- |
| A板K1～K12 | 0～11 / FSR1～12 | 第一片Y0～Y11 | C4～B4 |
| B板K1～K4 | 12～15 / FSR13～16 | 第一片Y12～Y15 | C5～D♯5 |
| B板K5～K12 | 16～23 / FSR17～24 | 第二片Y0～Y7 | E5～B5 |

第二片Y8～Y15不扫描。键号按 `docs/UI交互设计.md` 从C4连续到B5；例如第一片Y15对应B板K4，第二片Y0对应B板K5。

两个串行数据输入都要接好；暂时不用的触摸板数据输入须接GND，不能悬空。压力模拟输入继续沿用已经测通的前端。

## 高云软件构建

1. 在Gowin IDE中打开本目录的 `test_velocity.gprj`。使用器件 `GW5AST-LV138FPG676AC1/I0`，Device Version C。
2. 将 `src/test/test_velocity.v` 中的 `test_velocity` 设置为顶层；不要选 `test_velocity_core` 或旧的测试顶层。
3. 在工程配置中将Verilog标准设为 **SystemVerilog-2017**，Verilog Include Path加入本工程相对目录 **`../../src/audio`**。现有源码中的 `../defines.vh` 依赖此包含目录，不需要修改公共源码。
4. 确认本工程采用 `test_velocity.cst` 和 `test_velocity.sdc`。GPRJ已包含ADC、压力扫描、完整UI和音频依赖，无需另加主工程的CST/SDC。
5. 运行 **Synthesize**，随后运行 **Place & Route**；也可运行全部流程。检查错误和时序报告，不能只看到综合完成就判断可下载。
6. 位流输出为 **`impl/pnr/test_velocity.fs`**。打开Gowin Programmer，选择板卡并将该文件配置为 **SRAM下载**，下载后按下再松开S0。

也可从本目录的PowerShell执行所附脚本，它会配置顶层、标准、包含路径与布局布线选项：

```powershell
& '<Gowin安装目录>/IDE/bin/gw_sh.exe' './build.tcl'
```

SDC保留现有PLL的自动时钟模型；当前PLL实际约98.245614MHz，标称48kHz音频对应约47971.49Hz。ADC再64分频，约1.535MHz。ADC时钟约束落在稳定存在的硬核CLK引脚，避免等价寄存器合并导致约束失效。仅豁免进入两级复位同步器的异步CLEAR输入，业务复位和数据路径继续检查。CST将PLL初始化逻辑约束在之前上板测试验证过的下部区域，不改变公共RTL或频率。

## LED与预期现象

| LED | 正常含义 |
| --- | --- |
| LED0 | 音频采样计数心跳，约1.46Hz闪烁，启动后约0.34秒首次变化 |
| LED1 | 有至少一个琴键触摸状态为1 |
| LED2 | 至少一个按住键的原始校准压力达到25% |
| LED3 | 至少一个按住键的原始校准压力达到75% |
| LED4 | 混音削顶锁存，S0清除；亮时当前音量比较可能受限幅影响 |
| LED5 | ADC超时、键盘事件FIFO溢出、UI配置/采样超时或音频欠载锁存，正常应灭 |

默认正弦波、5ms Attack、150ms Decay、70% Sustain、200ms Release。按住时压力音量最低保持5%，再乘以ADSR包络；所以触摸但压力为0时仍可能有微弱声音。没有触摸时仅按压FSR不触发音符。

默认 `AUDIO_SHIFT=2`，混音后除4，为和弦留余量，再饱和为16位。这会使单音比直接满幅输出更轻。测试很多重压琴键时若LED4亮，可将该参数改为3～5重新构建；测试单音且希望更响时可改为0或1。未接入效果器，UI总增益/音色增益在固定输入下均为1.0。

建议按以下顺序测试：

1. 不触摸任何键：无声，LED0闪烁，LED1/LED5灭。不要把心跳初始尚未翻转误判为停机。
2. 单独测试A板K1～K12，再测B板K1～K12：从C4到B5逐半音升高；按住只起音一次，松开产生释放尾音。
3. 按住一个键超过约0.2秒，待包络进入持续阶段，再轻压/重压对应FSR：只改变此音的音量；其他FSR不应改变此键音量。力度经过约5ms平滑，24路ADC轮询另有约5.2ms以上延迟。
4. 同时按住两三个键，分别改变压力：每个音独立变化。重点核对A板K12/B板K1以及B板K4/K5两个边界，排除12+12触摸映射与16+8压力映射接错。
5. 松开所有键：约200ms后完全静音；压力变化不能重新触发松开的音符。
6. 若LED5亮，先核对ADC接线、供电和触摸串行链路，修复后按S0清除锁存。若只有LED4亮，先减少和弦数量或增大 `AUDIO_SHIFT`。

## 校准与仿真

在顶层参数中调整 `PRESSURE_ZERO_CODES`、`PRESSURE_FULL_CODES`、`PRESSURE_DEADBAND_CODE`，无需改驱动。每键一个14位校准码，最低14位对应键0，最高14位对应键23；默认各键零点0、满量程1690、死区8，与之前的压力驱动相同。码值约等于分压后电压乘2048；满量程取正常重压的实测值，不能只按电阻标称值推断。

ModelSim当前目录设为工程的 `sim` 目录后运行：

```tcl
do do/test/run_test_velocity.do
```

需要映射Gowin `gw5a` 仿真库；若未映射，在本机Transcript设置 `env(GOWIN_HOME)` 为Gowin安装目录或IDE目录，脚本会建立独立厂商工作库。共享DO不保存本机绝对路径。

仿真使用真实键盘/ADC驱动、UI、32声部机架和I2S，并独立解码串行引脚。默认ADSR除法器采用32级流水的等价IP行为模型，已与厂商网表逐拍比对298个结果，覆盖整数/小数位、边界输入及中途复位；综合仍使用原厂IP。测试ADC模型只模拟数字协议及切通道残留；缩短了启动和模拟稳定等待，正式顶层默认参数不变。测试检查24路映射、24键独立音高/力度、15/16边界隔离、持续调压不重起音、5%下限、松开与尾音开始、复位，以及左声道PCM与右声道静音。完整200ms尾音仍按上述上板步骤试听确认。

需要使用厂商除法器门级网表执行同一测试时，在运行DO前设置下面变量。ModelSim Starter的容量限制可能使其非常慢；恢复默认行为模型时将该变量设为0。

```tcl
set TEST_VELOCITY_VENDOR_DIVIDER 1
do do/test/run_test_velocity.do
```

独立复核除法器模型与厂商网表的逐拍一致性，可运行 `do do/test/run_test_velocity_divider.do`；预期298个有效结果全部一致并打印PASS。

本次联合回归通过：184组键盘数据、712帧音频、左右声道各711个I2S字，0错误、0警告；包含全部24键/24路压力，以及键下标15/16（FSR16/17）的跨片隔离。独立IP比对也通过298个有效结果；该网表测试出现1条Starter容量性能提示，不是功能错误。
